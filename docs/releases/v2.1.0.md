# ries-rs v2.1.0

Programmatic search-budget recalibration for useful everyday equations. The
Rust, Python, and WebAssembly APIs now search deeply enough at their default
levels to find ordinary rational and integer equations while keeping the
browser's maximum level bounded.

## Changed

- `level_to_complexity(level)` is now symmetric `(40 + 2*level, 40 + 2*level)`
  for supported levels 0–5. Level 3 is 46/46; level 5 is 50/50. The prior
  scale was `(10 + 4*level, 12 + 4*level)`.
- This intentionally changes search coverage, latency, and result ordering for
  the **same** API level in Rust helper, Python, and WebAssembly consumers.
  Function signatures are unchanged, but callers relying on old level budgets
  or saved reproductions must recalibrate. Rust consumers may set explicit
  `GenConfig` bounds for reproducibility.
- The CLI `-l` scale remains `35 + 10*level` on each side. `MAX_API_LEVEL`
  remains 5.

## Fixed

- Batch and streaming searches preserve near-zero left-hand sides for a target
  of exactly zero. This permits an exact `x = ln(1)` match. For nonzero
  targets the existing near-zero pruning remains in place.

## Coverage and limitations

- At programmatic level 3 the retained match pool contains exact equations
  such as `2*x = 5`, `x = 5/2`, `x = 3/2`, `x = 2*6`, and `x = 6*7`.
- The parity-ranked 100-match pool can still omit a simple solved expression
  at level 5 even when the search explores it. The level-3 default retains
  these representative plain forms.
- Candidate WASM measurements ranged from milliseconds for common numbers to
  about 2.7 seconds for the hardest tested level-5 target. These timings are
  specific to the measured environment, not a general latency guarantee.

## Distribution and citation

The tag-driven release workflow publishes Rust CLI archives, the
WebAssembly packages, Python wheels/source distribution, and the Rust/Python
registry packages. No version DOI is recorded for v2.1.0 until a Zenodo
archive and DOI are independently verified.
